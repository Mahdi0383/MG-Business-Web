# MG Business Web

سامانه تحت وب مدیریت کسب‌وکار MG؛ هدف محصول، ارائه نسخه وب یکپارچه و ماژولار پلتفرم MG Business است.

## اجرای نسخه فعلی در Termux یا رایانه

این نسخه فعلی رابط استاتیک HTML/CSS/JavaScript است و برای اجرای پوسته فعلی به Node.js یا npm نیاز ندارد.

```sh
pkg update -y
pkg install git python -y
git clone https://github.com/Mahdi0383/MG-Business-Web.git
cd MG-Business-Web
python -m http.server 8080 --bind 0.0.0.0
```

مرورگر همان دستگاه: http://127.0.0.1:8080

برای دریافت تغییرات بعدی در نشست جداگانه:

```sh
cd ~/MG-Business-Web
git pull --ff-only
```

## اجرای سرور API و پایگاه داده محلی

برای فعال‌کردن API، ورود کاربران و ذخیره‌سازی SQLite (به‌جای حالت صرفاً مرورگری):

```sh
python server.py
```

به‌صورت پیش‌فرض سرور فقط روی `127.0.0.1:8080` گوش می‌دهد. سپس `http://127.0.0.1:8080` را باز کنید. فایل پایگاه داده بیرون از پوشه عمومی سایت و در `~/.mg-business-data/mg-business.sqlite3` نگهداری می‌شود. مسیر داده را می‌توان با متغیر محیطی `MG_DATA_DIR` تغییر داد.

API فعلی:
- `GET /api/health` و `GET /api/setup-status`
- `POST /api/setup` برای ایجاد اولین کسب‌وکار و حساب مالک (رمز حداقل ۱۲ نویسه)
- `POST /api/login` و `POST /api/logout`
- `GET /api/me`
- `GET/POST /api/transactions` و `DELETE /api/transactions/{id}`

توکن نشست به‌صورت hash در SQLite نگهداری می‌شود؛ رمز عبور با PBKDF2-HMAC-SHA256 و salt تصادفی ذخیره می‌شود. تراکنش‌ها به tenant محدود هستند و تغییرات مهم در audit log ثبت می‌شوند. این API پایه هنوز جایگزین بازبینی امنیتی مستقل، TLS، محدودسازی تلاش ورود، مدیریت کاربران و مجوزهای کامل قبل از انتشار عمومی نیست. برای دسترسی از شبکه عمومی، سرور را مستقیم بدون HTTPS و تنظیمات امنیتی در معرض اینترنت قرار ندهید.

## قابلیت‌های پیاده‌سازی‌شده فعلی

- داشبورد واکنش‌گرا با رابط فارسی و راست‌چین.
- ناوبری اولیه ماژول‌های کافه، گیم‌نت، حسابداری، مشتریان، انبار، گزارش‌ها و تنظیمات.
- ثبت و حذف تراکنش‌های پایه درآمد و هزینه.
- جست‌وجوی تراکنش‌ها و محاسبه مجموع درآمد، هزینه و مانده.
- اعتبارسنجی مشترک تراکنش‌ها در `core.js`؛ مبلغ صحیح و مثبت، نوع، شناسه، تاریخ و محدودیت طول داده‌ها بررسی می‌شوند.
- خروجی پشتیبان JSON و بازیابی پشتیبان با اعتبارسنجی ساختار، نسخه، تعداد رکوردها و شناسه‌های تکراری.
- ذخیره‌سازی محلی در مرورگر.\n- سرور API اولیه مبتنی بر Python stdlib و SQLite، ایجاد فضای کاری/مالک، ورود با نشست bearer، ثبت/خواندن/حذف تراکنش tenant-scoped و audit log.
- پوسته PWA و cache فایل‌های اصلی برای بارگذاری آفلاین.
- بررسی ساختار HTML و ارجاعات DOM و تست‌های واحد هسته دامنه در GitHub Actions.

## وضعیت آمادگی و محدودیت‌ها

**این مخزن هنوز محصول آماده بهره‌برداری تجاری نیست.** داشبورد و تراکنش‌های محلی قابلیت‌های پایه‌اند و وجود آن‌ها به معنی پیاده‌سازی ماژول‌های عملیاتی نیست.

موارد زیر هنوز پیاده‌سازی نشده‌اند و برای انتشار واقعی ضروری‌اند:

- Backend و API امن، پایگاه داده مرکزی و مهاجرت‌های نسخه‌بندی‌شده.
- احراز هویت، مدیریت نشست، نقش‌ها و مجوزهای دقیق و جداسازی داده کسب‌وکارها.
- حسابداری دوبل، اسناد مالی، دفتر کل، بستن دوره و گزارش‌های قابل اتکا.
- عملیات کامل کافه، سفارش، میز، منو، افزودنی‌ها، صندوق و چاپ فاکتور.
- عملیات گیم‌نت، دستگاه، تایمر، تعرفه، رزرو و تسویه.
- مشتریان، باشگاه وفاداری، انبار، خرید، تأمین‌کنندگان و کنترل موجودی.
- همگام‌سازی چنددستگاهی، صف عملیات آفلاین، حل تعارض و جلوگیری از ثبت تکراری.
- پشتیبان‌گیری زمان‌بندی‌شده سمت سرور، بازیابی آزمایش‌شده، ثبت رویدادهای ممیزی و مانیتورینگ.
- تست‌های یکپارچه، مرورگر، امنیت، کارایی و سناریوهای بازیابی.

## اصول معماری هدف

- رابط PWA واکنش‌گرا با پشتیبانی فارسی/انگلیسی و RTL/LTR.
- API و لایه دامنه مستقل از رابط کاربری.
- SQLite برای استقرار تک‌فروشگاهی اولیه و امکان مهاجرت به پایگاه داده سروری در استقرار چندکاربره.
- هر عملیات مالی در تراکنش پایگاه داده انجام شود و اسناد حسابداری تغییرناپذیر و قابل ممیزی باشند.
- هر رکورد تجاری به فضای کاری/کسب‌وکار مربوط باشد و مجوزها در سمت سرور اعمال شوند.
- قابلیت آفلاین با صف عملیات و کلید idempotency طراحی شود؛ localStorage به‌تنهایی راهکار همگام‌سازی یا ذخیره امن داده مالی نیست.
- فعال‌سازی ماژول‌ها از طریق لایسنس، بدون جدا کردن داده‌ها و منطق مشترک.

GitHub Pages یا سرور استاتیک صرفاً فایل‌های رابط را ارائه می‌کند و به‌تنهایی Backend، احراز هویت یا پایگاه داده چندکاربره فراهم نمی‌کند.
