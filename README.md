# MG Business Web

پلتفرم وب مستقل MG Business برای مدیریت یکپارچه فروش، انبار، مشتریان، حسابداری، کافه/رستوران و گیم‌نت.

## وضعیت فعلی توسعه
- رابط React + Vite فارسی و RTL فقط در صورت پیکربندی API واقعی اجرا می‌شود؛ fallback نمایشی و داده mock از ورودی اصلی برنامه حذف شده است.
- Backend با ASP.NET Core 10 و تفکیک Domain / Infrastructure / API.
- احراز هویت Identity API، توکن bearer، محدودیت تلاش ورود و rate limit.
- زیرساخت اولیه صف خروجی و صندوق ورودی پایدار در IndexedDB، Sync Agent، cursor امن و API ثبت/دریافت عملیات idempotent.
- PWA قابل نصب با cache آفلاین پوسته و منابع استاتیک؛ مسیرهای API، احراز هویت و sync cache نمی‌شوند.
- heartbeat دستگاه‌ها هر ۳۰ ثانیه و صفحه پایش اتصال برای Owner/Manager؛ قطع heartbeat بیش از ۹۰ ثانیه هشدار می‌شود.
- ساخت کسب‌وکار، شعبه و عضویت کاربران با نقش‌های مختلف.
- انتخاب tenant و branch در سرور اعتبارسنجی می‌شود؛ شناسه ارسالی کلاینت به‌تنهایی مجوز نیست.
- APIهای پایه مشتریان، کالا/انبار، اسناد حسابداری دوبل، فروش، پرداخت، آشپزخانه کافه و تایمر گیم‌نت ایجاد شده‌اند.
- تست‌های دامنه و یکپارچه SQLite و CI برای Backend اضافه شده‌اند.
- SQLite برای توسعه/آزمایش و PostgreSQL برای استقرار مرکزی پشتیبانی می‌شود.

این پروژه هنوز نسخه عملیاتی یا آماده استفاده تجاری نیست. مهاجرت اولیه EF Core برای PostgreSQL و model snapshot در مخزن ثبت شده‌اند؛ اجرای migration در زمان شروع API فقط با تنظیم صریح فعال می‌شود. برای استقرار SQLite هنوز migration جداگانه لازم است. مجوزدهی ماژولار، خرید/تأمین‌کننده، مالیات، حساب تفصیلی مشتری، سفارش آنلاین، رزرو و باشگاه مشتریان هنوز تکمیل نشده‌اند. صف IndexedDB و API journal فعلی زیرساخت انتقال هستند و هنوز به گردش‌های فروش/انبار/حسابداری متصل نشده‌اند؛ رویدادهای دریافتی نیز هنوز به مدل‌های عملیاتی اعمال نمی‌شوند. failover، fencing، conflict resolution، MG Master و MG Control Center هنوز پیاده‌سازی نشده‌اند.

## اجرای رابط وب
برای اجرای نسخه متصل به API واقعی:
```bash
npm install
npm run dev
```

برای اتصال به Backend واقعی:
```bash
cp .env.example .env.local
```
سپس در `.env.local` مقدار `VITE_API_BASE_URL` را روی نشانی واقعی API تنظیم کنید. بدون این مقدار برنامه عمداً بالا نمی‌آید تا اطلاعات آزمایشی با داده واقعی اشتباه نشوند. در Backend نیز origin رابط وب باید در `Cors__AllowedOrigins__0` مجاز شده باشد؛ برای Vite محلی مقدار معمول `http://localhost:5173` است. بعد از تغییر فایل env، Vite را دوباره اجرا کنید.

با تنظیم API URL، برنامه ورود، انتخاب کسب‌وکار/شعبه، کالاها، مشتریان، حساب‌ها و سرفصل‌های پایه، ثبت فاکتور فروش، صف آشپزخانه و شروع سانس گیم‌نت را به API واقعی متصل می‌کند. بستن سانس گیم‌نت و چندین ماژول دیگر هنوز در رابط زنده تکمیل نشده‌اند. توکن‌ها فعلاً در `sessionStorage` نگهداری می‌شوند؛ این نسخه هنوز برای استقرار عملیاتی نهایی آماده نیست.

ساخت production:
```bash
npm run build
```

## اجرای API
نیازمند .NET 10 SDK:
```bash
dotnet run --project backend/src/MG.Business.Api/MG.Business.Api.csproj
```

مستندات API و محدودیت‌های استقرار در [backend/README.md](backend/README.md) و اصول معماری در [docs/architecture/FOUNDATION.md](docs/architecture/FOUNDATION.md)، [پروتکل آفلاین و failover](docs/architecture/offline-first-ha-protocol.md) و [MG Control Center و لایسنس](docs/architecture/control-center-and-licensing.md) قرار دارند.

## انتشار آزمایشی
GitHub Pages فقط فایل‌های استاتیک frontend را میزبانی می‌کند؛ API و پایگاه داده باید روی زیرساخت جداگانه اجرا شوند. انتشار عمومی پس از merge شدن تغییرات و فعال‌سازی Pages روی شاخه اصلی انجام می‌شود؛ در حال حاضر این پروژه هنوز نسخه منتشرشده عملیاتی ندارد.

## اصول غیرقابل مذاکره
- اطلاعات هر کسب‌وکار باید به‌صورت امن از سایر کسب‌وکارها جدا باشد.
- داده‌های مالی و موجودی باید دارای تاریخچه و قابلیت حسابرسی باشند.
- ثبت فروش، پرداخت، گردش موجودی و سند مالی باید در یک تراکنش سازگار انجام شود.
- قابلیت‌های آفلاین باید صف عملیات پایدار و همگام‌سازی قابل تکرار داشته باشند.
- هیچ قابلیت نمایشی یا mock نباید به‌عنوان قابلیت عملیاتی معرفی شود.
- قبل از استفاده از داده واقعی، migration، پشتیبان‌گیری، امنیت و تست استقرار باید تکمیل شوند.
